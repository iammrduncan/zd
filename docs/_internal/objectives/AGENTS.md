# Objective-record instructions

These instructions apply to `docs/_internal/objectives/` and its child folders.

- Treat `todo.txt`, `todo-archive.txt`, `FEEDBACK.md`, `feedback-archive.md`, and
  `agent-findings.md` as durable work records.
- Follow `way-of-working/` before changing task or feedback state.
- Preserve raw human feedback verbatim when archiving it.
- Do not move implementation plans or session evidence into user-facing documentation.
- Use ADRs for accepted architecture and ZSIPs for meaningful proposals. Do not make an objective
  record architecture authority.
