# Internal-record instructions

These instructions apply to `docs/_internal/` and its child folders.

Keep repository operations, historical analysis, promotion material, and implementation evidence
here when they are useful but are not active objective state or user guidance.

- Put accepted architecture in `docs/adr/`.
- Put meaningful proposals and deliberation in `docs/zsip/`.
- Put active work state and feedback in `docs/_objectives/`.
- Put released product guidance in `docs/user-facing-docs/`.
- Do not add an audit folder. Extract durable decisions, then remove temporary audit reports.
